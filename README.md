# kv-bridge

A Rust (2024 edition) demo that relays and rotates secrets between two HashiCorp Vault dev instances: a **Cloud Vault** and an **Antenna Vault**. All addresses and tokens are loaded from a `.env` file generated by `setup.bash`.

## What it does

1. Bootstraps Cloud Vault: writes `secret/rotation/secret` and `secret/data` (`name`, `age`, `birthday`)
2. Reads the bootstrap secret from Cloud and relays (copies) it to Antenna Vault, then displays the copies for verification
3. Copies `secret/data` from Cloud to Antenna
4. Rotates the secret in Cloud, stores the new Antenna token in Cloud, reads it back, and pushes the rotated secret to Antenna
5. Confirms a revoked (OLD) Cloud token is rejected with HTTP 403

## Prerequisites

- Docker + Docker Compose
- The Vault CLI is bundled in the `hashicorp/vault:latest` images used by `docker compose`; `setup.bash` runs Vault commands via `docker exec`
- Rust toolchain (edition 2024, Rust 1.85+)

## Usage

```bash
docker compose up -d
./setup.bash   # configures both vaults, creates tokens, writes .env, then runs cargo run
```

`setup.bash` creates short-lived tokens (2h / 10s / 90s TTL), so run the demo soon after setup. Re-run `setup.bash` to refresh tokens. If you prefer to run the Rust demo separately, just run `cargo run` after `.env` exists.

## Environment variables

All variables are loaded from `.env` at startup (see `.env.example` for the template). `setup.bash` writes the `NEW_*` and `OLD_*` tokens:

| Variable                  |                 Meaning                 |                        Set by |
|:--------------------------|:---------------------------------------:|------------------------------:|
| `CLOUD_VAULT_ADDR`        |           Cloud Vault address           | `.env.example` / `setup.bash` |
| `NEW_CLOUD_VAULT_TOKEN`   |        Current Cloud Vault token        |                  `setup.bash` |
| `OLD_CLOUD_VAULT_TOKEN`   | Revoked Cloud Vault token (expects 403) |                  `setup.bash` |
| `ANTENNA_VAULT_ADDR`      |          Antenna Vault address          | `.env.example` / `setup.bash` |
| `NEW_ANTENNA_VAULT_TOKEN` |       Current Antenna Vault token       |                  `setup.bash` |
| `OLD_ANTENNA_VAULT_TOKEN` |       Revoked Antenna Vault token       |                  `setup.bash` |

## How secrets are handled

- `.env` is loaded at startup with `dotenvy`
- `.env` is git-ignored (see `.gitignore`)
- Secrets are printed to the console during the demo, so this is for demonstration only — never use it with real secrets

## Notes

- Dev-mode Vault is in-memory and insecure by design; never use for real secrets
- The bridge relays secrets the same way AWX/consumers would read from Antenna Vault
